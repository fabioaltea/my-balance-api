# Authentication System Documentation\n\n## Overview\n\nThis document describes the new authentication system implemented for the MyBalance API. The system follows the **token separation** pattern where Google OAuth is used solely for user identification, and the backend issues its own JWT tokens for API access.\n\n## Architecture\n\n### High-Level Flow\n\n1. **Client Authentication**: User authenticates via Google OAuth (Authorization Code + PKCE)\n2. **Token Exchange**: Client sends authorization code to `/auth/google/callback`\n3. **Backend Processing**:\n - Verifies Google ID token\n - Exchanges code for Google tokens\n - Encrypts and stores Google refresh token\n - Issues internal JWT access + refresh tokens\n4. **API Access**: Client uses only internal JWTs for all API calls\n5. **Server-side Google API**: Backend uses stored Google refresh token for Google Sheets access\n\n### Token Types\n\n| Token Type | Purpose | TTL | Storage |\n|------------|---------|-----|----------|\n| JWT Access Token | API authentication | 10 minutes | Client memory |\n| JWT Refresh Token | Token renewal | 30 days | Client secure storage |\n| Google Refresh Token | Server-side Google API access | Permanent | Database (encrypted) |\n| Internal Refresh Token | Session management | 30 days | Database (hashed) |\n\n## Security Features\n\n### 🔐 Token Encryption\n- Google refresh tokens encrypted using AES-256-GCM\n- Internal refresh tokens hashed using SHA-256\n- Constant-time comparison for token verification\n\n### 🔄 Token Rotation\n- Refresh tokens rotated on every use\n- Expired sessions automatically cleaned up\n- Device-specific session tracking\n\n### 🛡️ Rate Limiting\n- Authentication endpoints: 10 requests/15 minutes\n- Sensitive endpoints: 5 requests/15 minutes\n- Per-IP basis with standard headers\n\n### 🔑 JWT Security\n- RS256 algorithm (RSA signatures)\n- Short-lived access tokens (10 minutes)\n- Proper audience and issuer validation\n\n## API Endpoints\n\n### Authentication Endpoints\n\n#### `POST /auth/google/callback`\nExchange Google authorization code for internal tokens.\n\n**Request:**\n`json\n{\n  \"authorizationCode\": \"string\",\n  \"codeVerifier\": \"string\",\n  \"deviceId\": \"string\"\n}\n`\n\n**Response:**\n`json\n{\n  \"success\": true,\n  \"accessToken\": \"jwt_access_token\",\n  \"refreshToken\": \"internal_refresh_token\",\n  \"user\": {\n    \"id\": \"uuid\",\n    \"email\": \"user@example.com\",\n    \"name\": \"User Name\",\n    \"picture\": \"https://...\"\n  }\n}\n`\n\n#### `POST /auth/refresh`\nRefresh expired access token.\n\n**Request:**\n`json\n{\n  \"refreshToken\": \"string\",\n  \"deviceId\": \"string\"\n}\n`\n\n**Response:**\n`json\n{\n  \"success\": true,\n  \"accessToken\": \"new_jwt_access_token\",\n  \"refreshToken\": \"new_internal_refresh_token\"\n}\n`\n\n#### `POST /auth/passkey/login`\nAuthenticate using WebAuthn passkey.\n\n**Request:**\n`json\n{\n  \"passkeyAssertion\": {},\n  \"deviceId\": \"string\"\n}\n`\n\n#### `POST /auth/logout`\nRevoke current session.\n\n**Request:**\n`json\n{\n  \"deviceId\": \"string\"\n}\n`\n\n#### `GET /auth/profile`\nGet authenticated user profile (requires Bearer token).\n\n### Protected Endpoints\n\nAll Google Sheets endpoints now require authentication:\n\n- `GET /get` - Get spreadsheet data\n- `POST /update` - Update spreadsheet data\n- `POST /addMovement` - Add financial movement\n- `POST /append` - Append data to spreadsheet\n\n**Authentication Header:**\n`\nAuthorization: Bearer <jwt_access_token>\n`\n\n## Database Schema\n\n### Users Table (Extended)\n`sql\nCREATE TABLE users (\n  id UUID store Google tokens\n2. **Use Internal Tokens**: Store and use only the internal JWT tokens\n3. **Token Refresh Logic**: Implement automatic token refresh when access token expires\n4. **Authorization Headers**: Send `Authorization: Bearer <token>` instead of Google tokens\n\n### Example Client Code\n`` typescript\n// After Google OAuth\nconst response = await fetch('/auth/google/callback', {\n  method: 'POST',\n  headers: { 'Content-Type': 'application/json' },\n  body: JSON.stringify({\n    authorizationCode: code,\n    codeVerifier: verifier,\n    deviceId: getDeviceId()\n  })\n});\n\nconst { accessToken, refreshToken } = await response.json();\n\n// Store tokens securely\nsecureStorage.setItem('accessToken', accessToken);\nsecureStorage.setItem('refreshToken', refreshToken);\n\n// Use in API calls\nfetch('/get', {\n  headers: {\n    'Authorization': `Bearer ${accessToken}`\n  }\n});\n ``\n\n### Token Refresh Implementation\n`` typescript\nclass ApiClient {\n  async makeRequest(url: string, options: RequestInit = {}) {\n    let accessToken = secureStorage.getItem('accessToken');\n    \n    const response = await fetch(url, {\n      ...options,\n      headers: {\n        ...options.headers,\n        'Authorization': `Bearer ${accessToken}`\n      }\n    });\n    \n    if (response.status === 401) {\n      // Token expired, refresh it\n      accessToken = await this.refreshToken();\n      \n      // Retry original request\n      return fetch(url, {\n        ...options,\n        headers: {\n          ...options.headers,\n          'Authorization': `Bearer ${accessToken}`\n        }\n      });\n    }\n    \n    return response;\n  }\n  \n  async refreshToken(): Promise<string> {\n    const refreshToken = secureStorage.getItem('refreshToken');\n    const response = await fetch('/auth/refresh', {\n      method: 'POST',\n      headers: { 'Content-Type': 'application/json' },\n      body: JSON.stringify({\n        refreshToken,\n        deviceId: getDeviceId()\n      })\n    });\n    \n    const { accessToken: newAccessToken, refreshToken: newRefreshToken } = await response.json();\n    \n    secureStorage.setItem('accessToken', newAccessToken);\n    secureStorage.setItem('refreshToken', newRefreshToken);\n    \n    return newAccessToken;\n  }\n}\n ``\n\n## Migration Guide\n\n### Troubleshooting\n\n### Common Issues\n\n1. **\"Invalid or expired access token\"**\n - Implement token refresh logic in client\n - Check JWT key configuration\n\n2. **\"No Google refresh token found\"**\n - User needs to re-authenticate via Google OAuth\n - Check database encryption key\n\n3. **\"Session expired\"**\n - User needs to log in again\n - Check refresh token rotation logic\n\n4. **Rate limit exceeded**\n - Implement exponential backoff in client\n - Check for excessive authentication attempts\n\n### Debug Mode\nEnable debug logging by setting:\n`env\nDEBUG=auth:*\n`\n\nThis will log authentication-related operations for troubleshooting.
